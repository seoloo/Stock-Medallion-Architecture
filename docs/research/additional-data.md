## 출발점과 수집 목적

처음 질문은 **“주가가 오른 만큼 기업의 사업 성과도 좋아졌는가? 외국인은 매도하는데 주가는 오른다면 무엇을 더 확인해야 하는가?”**였다.

기존 과제에서는 교환받은 레거시 데이터를 정제·표준화했다. 이번에는 이 질문을 검토하기 위해 주가·수급, 가치평가, 실적·현금흐름, 사업·전망의 **네 가지 정보군을 확장 대상으로 정하고 필요한 외부 자료를 추가 수집**했다. 이미 있는 외국인 수급·현금흐름·재고·유형자산 취득 자료는 재사용했다. 네 정보군의 모든 항목을 새로 수집했다는 뜻은 아니다.

## 출처와 수집 방법

- [네이버 증권](https://m.stock.naver.com/domestic/stock/005930/total)의 공개 JSON 응답을 HTTP GET으로 수집했다. `https://m.stock.naver.com/api/stock/{종목코드}/basic`, `/integration`, `/finance/annual`, `/finance/quarter`를 사용했다. 공식 계약 API가 아니므로 응답 형식 변경 시 수집 코드 점검이 필요하다.
- [삼성전자 2026년 1분기 실적발표](https://images.samsung.com/is/content/samsung/assets/global/ir/docs/2026_1Q_conference_eng.pdf): PDF 6쪽의 사업부 수치와 7쪽 전망. 사업부 매출은 내부거래가 포함되어 연결 매출과 단순 합산하지 않는다.
- [삼성전자 2026년 1분기 보고서](https://images.samsung.com/is/content/samsung/assets/global/ir/docs/2026_1Q_Interim_Report.pdf): PDF 30쪽 연결 재고, 39쪽 연결 현금흐름. KRW 백만원 열과 인접 USD 열을 구분해 확인했다.
- [SK하이닉스 2026년 1분기 실적발표](https://news.skhynix.com/en/q1-2026-business-results-1/): 본문은 이미지형이므로 메뉴 텍스트를 실적으로 취급하지 않았다. 페이지가 연결한 공식 인포그래픽을 확보해 수치·전망을 시각적으로 확인했다.

수집한 173개 응답의 URL·수집시각(KST)·원문 SHA-256·경로·원문 바이트를 `research_source`에 저장했다. 원문은 로컬 `build/value-evidence/collected/raw/`에도 있다. 인증정보와 추가 원문 파일은 Git에 포함하지 않았다. 수집 오류는 0건이다.

## 단위·기간·정밀도

- 네이버 재무 요약 금액은 억원에서 원으로 변환한다. EPS·BPS·배당금은 원/주, PER·PBR은 배수, 백분율은 소수 비율로 변환한다. 원래 문자열도 보존한다.
- `value`는 MySQL `DECIMAL(38,10)`이다. `-`, `N/A`, 빈값은 NULL이며 0으로 채우지 않는다. 전망치는 `is_estimate='Y'`로 구분한다.
- 공식 보고서 수치는 별도 표에 두고 연결(CFS), 기말(ASOF)·3개월(Q3M), 원문 페이지와 확인 상태를 남긴다. 재고는 잔액이며 현금흐름은 기간값이다. 유형자산 취득 현금유출은 원문의 음수 부호를 보존하며 이를 회사 전체 CAPEX로 단정하지 않는다.
- 삼성전자 실적발표의 사업부 수치와 SK하이닉스 이미지 수치는 발표자료의 반올림 정밀도를 유지한다. 동일 기간의 다른 자료와 숫자가 다르면 원문별로 보존하고 자동 덮어쓰기하지 않는다.

## 과거 분석과 새 수집 시점의 구분

기존 README 6장의 분석 기준일은 **2026-06-30**이다. 새 자료는 **2026-10-16 수집 스냅샷**이고, 추가 일별 수급의 최근 구간은 **2026-10-08~10-15**다. 조회 중인 현재 배수·추정 EPS를 6월 말의 값으로 사용하지 않는다.

연간/분기 표의 기간은 실적 귀속 기간이며, 그 숫자를 시장이 처음 알 수 있었던 날짜를 뜻하지 않는다. 정확한 최초 공시일·당시 전망 버전이 검증되지 않은 추가 재무·가치평가·공식 수치는 `historical_pit_eligible='N'`으로 적재했다. 공식 발표자료도 수집한 파일 버전의 당시 동일성을 검증하지 않았으므로 과거 백테스트 피처로 자동 연결하지 않는다.

일별 PER/PBR 전체 역사, 과거 시점별 컨센서스, 20종목 전체 사업부·제품별 정형 수치까지 확보한 것은 아니다. 현재 자료는 탐색·근거 검토와 팀의 규칙 기반 예상에 사용한다. [20종목 과열 가능성 예상](assessment.md)을 추가했으며, 거품 여부나 적정 주가를 확정하는 모델은 아니다.

## 기존 데이터에서 확인한 실제 사례

같은 2026-06-01~06-30 구간에서, 주가 수익률은 양 끝 종가의 비율이고 순매수는 6월 1일 이후 20개 거래일의 합이다. 보유율 변화는 양 끝 차이(%p)다.

| 종목 | 주가 수익률 | 외국인 20거래일 순매수 | 외국인 보유율 변화 |
|---|---:|---:|---:|
| SK하이닉스 | +11.02% | -7,392,456주 | -0.98%p |
| 삼성전자 | -6.20% | -76,545,220주 | -1.34%p |

SK하이닉스에서는 주가 상승과 외국인 이탈이 함께 관측됐다. 삼성전자는 같은 구간 주가도 하락했으므로 같은 유형의 사례로 표시하지 않았다. 외국인 매도만으로 거품을 확정할 수는 없다. 추가 수집 자료를 통해 실적·현금·사업 전망·평가 배수를 더 확인할 수 있다.

## 재현·검증

저장소 루트에서 실행한다. Python 3, PyMySQL과 Poppler의 `pdftotext`가 필요하다. 수집은 새 출력 폴더에만 쓰고, DB 적재는 신규 스키마만 생성한다. 고정 DDL의 DROP/USE 부분은 실행하지 않는다. GitHub 데이터 적재 중 실패한 스키마는 해당 실행의 소유 기록이 있을 때 기존 테이블을 전량 대사하고 재삽입하지 않는다. 추가 수집 테이블 적재가 이미 시작된 실패 스키마는 보존하고 새 이름을 사용한다. 공식 수치의 수동 추출은 시각 검토한 PDF·이미지 해시에 고정했다. 원문이 바뀌면 추출을 중단하고 재검토해야 한다.

```bash
python3 scripts/check_handoff.py
python3 scripts/research/collect.py --out build/research-new-run
python3 scripts/research/enrich_official.py --collection build/research-new-run
python3 scripts/research/load_mysql.py --collection build/research-new-run --schema tz_teamzero_research_new_run
python3 -m unittest discover -s scripts/research -v
```

비밀번호는 적재 명령에서 로컬 입력한다. 새 수집 실행은 그 실행 시점의 스냅샷이며 2026-10-16 수치를 그대로 재현하지는 않는다. 당시 값은 로컬 원문과 MySQL 저장 원문으로 검증할 수 있다.

실행 결과: 고정 인계본 75파일 무결성 PASS, Silver/Gold 19테이블 전행·전열 값 대사 PASS, 추가 7테이블 전행·전열 값 대사 PASS, 원문 173개 저장 SHA-256 대사 PASS, 독립 SQL 검사 9개 PASS, 회귀 검사 4개 PASS. 기존 전망 DB의 모든 기본 테이블은 전후 전체 값 해시가 같았다.
